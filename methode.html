Process framework

Method — CMMI Level 3

Helveticore commits to delivering its technology bricks at CMMI-DEV v2.0, Level 3 “Defined” maturity. The process is defined, documented and reused identically from one project to the next.

Hybrid lifecycle

LevelApproachRole
Macro-architectureV-ModelTop-down design, bottom-up validation & verification (system → components → integration tests)
Micro-architectureTDDTest-driven development of proprietary components, with mocked inputs
IntegrationCBSEQualification and reuse of proven open-source components; in-house builds for anything requiring strict control

Mandatory artifacts per project

Every projects/<project>/ folder must contain, at minimum:

requirements/   REQ.md, RTM.md          (requirements + traceability matrix)
design/         SDD.md, decision-log.md  (design + decision log)
testbench/      README.md                 (virtual test bench plan)
performance/    README.md                 (KPI measurement plan)
src/            technical sub-projects + README.md per sub-project
README.md       project charter (scope, KPIs, risks, milestones)

“Build vs Reuse” rule (CBSE)

Reuse

An open-source component when it meets footprint and latency criteria and its protocol compliance is proven (e.g. pymodbus, Eclipse Mosquitto).

Build in-house

Any component requiring strict “Fail-Fast” behavior, a proprietary data schema, or a CMMI L3 quality guarantee (e.g. protocol adapters, behavioral analysis engines).

Each choice is recorded in design/decision-log.md (criteria, options, decision, rationale) — see the EdgeStream-GW decision log.
