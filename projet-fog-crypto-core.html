Fog-Crypto Core

An HW/SW co-design FPGA accelerator dedicated to offloading critical computations and securing IoT nodes — data integrity and confidentiality at the source for sensitive industrial infrastructures. The AES-256-GCM crypto datapath is now implemented and validated bit-exact in simulation.

Project card

  • Developed by — Helveticore OÜ (Estonia)
  • Hardware target — AMD Xilinx Zynq UltraScale+ MPSoC — baseline ZU3EG
  • Maturity — CMMI Level 3 “Defined”
  • Discipline — HW/SW co-design, SystemVerilog (Verilator + cocotb)
  • Source document — SDD IEEE 1016 + ICD (frozen HW/SW boundary)

Positioning & targets

Two disjoint data paths: authenticated encryption (AES-256-GCM at line rate) and real-time sensor pre-processing (CIC / moving average) — offloading the Cortex-A53.

  • CPU offload — ÷ 2 (MVP) / ÷ 10 (Phase 2), bench pending.
  • Line rate — 100 MbE (MVP) / 1 GbE (Phase 2), zero frame loss.
  • Latency — AES ≤ 100 cycles; crypto end-to-end ≤ 20 µs (targets).

Implemented crypto datapath

src/crypto-engines/ — SystemVerilog, validated bit-exact against a vendored golden reference (BLu85 AES-256-GCM).

  • aes256_core.sv — iterative AES-256 encrypt (15 cycles/block). bit-exact
  • ghash_core.sv — pipelined GHASH GF(2¹²⁸) multiplier (CLMUL + reduction, 4 stages). bit-exact
  • ghash_accumulator.sv — GHASH feedback accumulator. bit-exact
  • aes256_gcm.sv — AES-256-GCM datapath (encrypt + decrypt + tag). bit-exact
  • aes256_gcm_saf.sv — store-and-forward + fail-safe (REQ-FOG-SEC-002). validated
  • aes256_gcm_axis.sv — AXI4-Stream wrapper. validated
  • sg_dma.sv — SG-DMA / descriptor-engine skeleton. validated
  • pl_mac.sv — PL MAC skeleton (802.3x PAUSE + tx_er fail-safe). validated
  • fog_crypto_top.sv — integration top (crypto + SG-DMA + PL MAC). validated

Milestones & risks

Milestones

  • M0 · Golden reference (BLu85 AES-256-GCM) vendored & validated — done.
  • M1 · Cross-check harness + SystemVerilog path proven (Verilator + cocotb) — done.
  • M2 · AES-256 core + GCM datapath in SystemVerilog — done.
  • M3 · Bit-exact diff vs golden model (3,933 CAVP vectors) — done.
  • M4 · Store-and-forward + fail-safe (REQ-FOG-SEC-002) — done.
  • M5 · Integration top + pipelined GHASH + SG-DMA + PL MAC + OOC synthesis script — done.
  • Next · OOC synthesis on ZU3EG (Vivado), then on-board benchmark (project milestone 4).

Key risks (RSK)

  • Meeting FPGA timing (≥ 150 MHz) — mitigated by the pipelined GHASH and the OOC synthesis script + XDC; Vivado run pending.
  • HW/SW coherence of the AXI4 SG-DMA — mitigated by the frozen ICD and VFIO (D-6).
  • Key security and side channels — MVP uses BBRAM key; Phase 2 adds DOM masking, CSU PUF + AES-256-KW (D-4).
Current state: the CMMI Level 3 specification set (Rev 2.0) is frozen — 25 tiered requirements, RTM, SDD, ICD, 17 decisions — and the AES-256-GCM crypto datapath is implemented and validated bit-exact against the full NIST CAVP GCM AES-256 corpus (3,933 vectors) plus a pycryptodome sweep, cross-checked against the vendored golden reference. Store-and-forward / fail-safe fault injection passes. The OOC synthesis script and XDC for ZU3EG are prepared (Vivado required to run). The headline KPIs (CPU ÷ 2/÷ 10, line rate) are defined and traceable but not yet bench-measured — that is the next, on-board milestone.
