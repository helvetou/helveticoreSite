# EdgeStream-GW — Volume-reduction KPI report (REQ-001b)

_Date: 2026-10-28 · Milestone 1 · Generated by `measure_volume_reduction.py`_

## Target

- Cloud-bound (northbound) data-volume reduction **≥ 75%**.

## Scenario

| Parameter | Value |
| --- | --- |
| Meters | 50 (deterministic simulator, seeds 0–4) |
| Polling | 1 Hz, 300 s (5 min) |
| Aggregation window | 60 s (`WindowAggregator`, reducer `rms`) |
| Protocol | Modbus RTU (FC 03) |
| Northbound volume | UTF-8 JSON bytes of the normalized `Frame` stream |

## Method

The end-to-end chain runs without hardware:

```
50-meter simulator → Modbus RTU adapter → Frame → Edge Analytics PS WindowAggregator
```

- **Raw volume** = JSON bytes of every parsed `Frame` (what would be published
  before aggregation).
- **Aggregated volume** = JSON bytes of the one `Frame` emitted per meter per
  60 s window (RMS + `.min` + `.max` per quantity).
- JSON serialization is used as the canonical measure of normalized northbound
  telemetry volume (MQTT/OPC UA publish the `Frame` schema). The raw Modbus ADU
  wire volume (195 000 bytes over the run) is southbound and reported only for
  context.

## Results (5 seeds)

| Metric | Raw | Aggregated | Reduction |
| --- | --- | --- | --- |
| Frames | 15 000 | 250 | **98.33 %** |
| Measurements | 60 000 | 3 000 | **95.00 %** |
| JSON bytes (mean) | 6 666 214 | 262 004 | **96.07 %** |

Byte-reduction across seeds: min **96.07 %**, mean **96.07 %**, max **96.07 %**.

## Conclusion

**PASS** — the measured northbound volume reduction (96.07 %) exceeds the
≥ 75 % target by a wide margin, and is stable across seeds. The reduction is
structural: a 60 s window collapses 60 frames per meter into 1 (RMS + min/max),
realizing REQ-001b and the portfolio KPI.
