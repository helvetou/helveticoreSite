Bottom line: the gateway's core value — turning a high-frequency meter stream into a small, clean, normalized stream — is implemented, tested, and measured. What remains is the production pipeline around it (routing, publication, offline resilience, deployment).

What EdgeStream-GW is

An ultra-lightweight industrial software gateway that sits between physical perception nodes (meters, sensors, PLCs) and the Cloud. It reads raw time-series data, normalizes it into one strict shared Frame object, and shrinks it locally before publication — so the Cloud receives far less data while the important information is preserved.

Two hard KPIs drive the design:

  • −75 % data volume transmitted to the Cloud (target; measured 96.07 %).
  • Local actuation latency < 50 ms (fast path, no Cloud round-trip — Milestone 5).

Done (verified)

  • Milestone 0 — Baseline (milestone-0-baseline)
    • Fail-Fast protocol adapters: ModbusRtuAdapter + ModbusTcpAdapter behind one ProtocolAdapter interface.
    • Strict Pydantic v2 Frame schema (extra="forbid", bounded fields, non-empty measurements).
    • Edge Analytics PS: compute_stats, aggregate_window, dedupe, WindowAggregator.
    • Deterministic 50-energy-meter virtual test bench.
    • Technical report generator (makeTRM → .docx).
  • Milestone 1 — Volume-reduction KPI (milestone-1-volume-kpi)
    • End-to-end measurement: simulator → adapter → Frame → WindowAggregator.
    • Measured 96.07 % northbound byte reduction (target ≥ 75 %), stable across 5 seeds.

Honest framing: what is not there yet

At Milestone 1 this is a proven building block, not a deployable product. It reads simulated meters and shrinks data. Missing before production: south drivers (real polling), ingestion-core routing, northbound publication (MQTT/OPC UA), store-and-forward, the local action loop, and deployment. Without store-and-forward and northbound, the gateway has no way to send data or survive a network outage.

Known hardening items before production (full list in the technical report):

  • Observability and a boundary policy (log + quarantine malformed frames).
  • Clock validation, bounded buffers, data-quality flags (stale/suspect).
  • Concurrency (per-device asyncio), external configuration, TLS + authn.
  • Failure-injection and soak tests; real-hardware calibration.
