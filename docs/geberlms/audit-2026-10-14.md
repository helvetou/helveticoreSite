## 1. Synthèse exécutive

L'audit a pour objet de vérifier **chaque affirmation** contenue dans le manuel de test
`docs/manual-dev.md`, en attribuant à chacune un verdict **PASS**, **FAIL** ou **BLOQUÉ**,
assorti d'une preuve observable (sortie de commande, schéma D1, arbre de fichiers ou
inspection de code).

**Résultat global :**

- ✅ **Conforme (PASS)** : prérequis, mise en place de la base, vérifications automatiques,
  pile frontend, et — par inspection statique — l'intégralité du câblage des scénarios §6.
- ⛔ **Bloqué (BLOQUÉ)** : l'exécution *navigateur* des scénarios §6, faute de serveur de
  développement démarrable sans identifiants Cloudflare.
- ❌ **Non-conformités (FAIL)** : **5 écarts**, dont **1 majeur** (instruction de démarrage
  non reproductible) et **1 fonctionnel** (activation/désactivation des coupons non
  implémentée).

Détail des écarts : voir §7. La base de code est **fonctionnellement saine** (206 tests
verts, build et typage propres) ; les non-conformités relèvent principalement de la
**documentation du manuel**, non du comportement applicatif.

## 3. Méthodologie

Trois familles de preuve ont été distinguées :

1. **Exécution automatisée** — commandes `npm`, migrations/seeds D1 locales, requêtes D1.

Règle appliquée : *aucun verdict sans preuve*. Une divergence entre le manuel et le code
est un écart (FAIL), jamais un ajustement silencieux du référentiel.

## 5. Scénarios fonctionnels (§6) — statut

### ⛔ Blocage d'exécution (raison précise)

Le serveur de développement **ne démarre pas sans identifiants Cloudflare**, alors que
ceux-ci ne figurent pas dans les prérequis du manuel (§1) :

- `npm run dev` (Vite) : l'adapter-cloudflare émule la plateforme via `getPlatformProxy`
  → échec « `Failed to start the remote proxy session … CLOUDFLARE_API_TOKEN` ».
  Constat : `GET /login` → **HTTP 500**.
- `wrangler dev` : bindings `DB`/`FILES`/`ASSETS` en mode `local`, mais le binding **`AI`
  est `remote`** → même erreur, le Worker ne démarre pas.

En conséquence, les scénarios §6 ont été vérifiés par **inspection statique du câblage**
(actions, guards de rôle, services) — tous présents et cohérents — mais **non validés en
live navigateur**.

## 7. Non-conformités (FAIL) et anomalies

### 7.1 — ❌ §3 : instruction de démarrage non reproductible (MAJEUR)
`npm run dev` exige `CLOUDFLARE_API_TOKEN` (ou `wrangler login` interactif), **non listé
dans les prérequis §1**. Sur un clone vierge, la page login renvoie HTTP 500/503.
→ *Action : documenter le prérequis et préciser que le dev local passe par la plateforme
Cloudflare (binding `AI` distant).*

### 7.2 — ❌ §6.5 : activation/désactivation des coupons non implémentée
Le manuel affirme « activer/désactiver » les coupons. La route `admin/coupons` n'expose que
`create` ; aucun action/service de bascule. Le champ `enabled` existe mais est uniquement
lu (affichage « désactivé ») et forcé `true` à la création.
→ *Action : implémenter le toggle, ou retirer l'affirmation du manuel.*

### 7.3 — ⚠️ §2 : migrations non idempotentes (MINEUR)
Relancer les migrations sur une base déjà migrée échoue : `table already exists` /
`duplicate column name`.

### 7.4 — ⚠️ §2 : `seed-admin.ts` non idempotent (MINEUR)
Échoue avec `UNIQUE constraint failed: users.email` si l'admin existe déjà (contrairement
à `seed-demo.ts`, qui supprime puis réinsère).

### 7.5 — ⚠️ §6.9/§7 : état initial de progression ambigu (MINEUR)
`seed-demo.ts` insère `progress.status='completed'` : la leçon de démo est **déjà terminée**
au premier affichage, ce qui affaiblit la démonstration de « Marquer comme terminé ».

## 9. Recommandations

1. **Manuel §1/§3** : ajouter le prérequis `CLOUDFLARE_API_TOKEN` (ou `wrangler login`) et
   préciser la dépendance à la plateforme Cloudflare pour le dev local.
2. **§6.5** : implémenter la bascule activer/désactiver des coupons, ou corriger le manuel.
3. Rendre **idempotents** les migrations et `seed-admin.ts` (ou documenter l'exigence de
   base vierge).
4. Rejouer l'audit navigateur complet dans un environnement doté d'identifiants Cloudflare.
5. Trivial : supprimer l'insertion `completed` du seed de démo, ou documenter l'état initial.
